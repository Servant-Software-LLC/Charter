## The scope correction — the plan was aimed at the wrong layer

The first pass reviewed the plan against itself and found it internally sound. It is. But **the plan did
not fix the issue it is named after**, and no guardrail in it could ever have said so.

Issue #221's own captured event wire shows `markers-rendered` and `focus-not-restored` firing **before**
`review-log-loaded`, with `items=0` and `panelHidden=false`. Two lines of the SDK explain it:

- `sdk/charter-annotate.js:92` — `state.log` is initialised to
  `{ comments: [], diagnostics: [], unreadable: [], selfEmail: null }`: a **literal empty log**, with no
  way to say *"not loaded yet."*
- `sdk/charter-annotate.js:4436` — `es.addEventListener('review-log', function () { emit('review-log-changed', {}); hydrateLog(); });`
  — the emit is synchronous, `hydrateLog()` is **fire-and-forget**.

So a render lands between the two with the initial empty log and reports the reviewer's note gone. Task 08
declines an **Unknown response**; at that moment **there is no response to decline**. Tasks 01–06 fix a
real, separate server defect (`ReviewLogRead.Empty`'s own doc comment admits the conflation, and
`ReviewLogDrain` reports exit 2 for a log it could not read) — but that is not #221.
