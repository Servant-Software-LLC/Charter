BLOCKERS/NOTES

- **NUGET HAS TWO INDEXES AND THEY LAG DIFFERENTLY.** Flat container first (~140s on 0.26.0, ~180s on
  0.25.0); the REGISTRATION index — which `dotnet tool update` resolves against — lags further and fails
  with *"is not found in NuGet feeds"*, which reads like the package was never published. Clearing the
  http-cache does NOT help (server-side). An explicit `--version` worked instantly on 0.25.0 and did NOT on
  0.26.0, so it wins the race often, not reliably. **Poll the registration index, then install.**
- **A CI WATCH'S EXIT CODE IS NOT THE VERDICT.** `gh run watch --exit-status` returned 0 for a run whose
  conclusion was `failure`. Always read `conclusion`, and check `headSha` equals the PR's `headRefOid` — a
  `gh pr update-branch` leaves the old run reporting success for a commit no longer in the PR. Both traps
  fired today.
- Standing authorization: **merge on green without asking**. Red still stops for a decision, unless it is a
  known filed flake in an area the change cannot touch.
- **The Python-heredoc pipeline EATS ONE LEVEL OF BACKSLASH.** `\\n` in a `<<'PY'` heredoc reaches the file
  as a real newline, three times today, each breaking the C# build. Use the Write/Edit tools for content
  with escapes, or build characters from code points (`(char)10`).
- Charter #212 made "no control character typed literally into a source file" a house rule; the new tests
  build every case from a code point and spell it as a JSON escape.

DOCTRINE (carried forward, plus new)

All prior doctrine still holds. New, and the first three are the session:

- **A TIMEOUT IS NOT EVIDENCE OF ABSENCE; IT IS EVIDENCE OF NOT KNOWING.** #217's probe collapsed both into
  one null and then DELETED the descriptor on it. #147 settled the same shape once already (a pid is a
  NEGATIVE signal only): weak evidence must not be treated as proof when the action taken on it destroys
  what would disprove it.
- **"NO MATCHES" AND "THE TOOL NEVER LOOKED" PRODUCE IDENTICAL OUTPUT.** Guardrails aimed this at us and it
  landed: our doc credited "ripgrep's default ignore rules" and prescribed `--no-ignore --hidden`. Measured —
  `--no-ignore` does NOTHING there (`.claude/` is not gitignored); `--hidden` is the flag; and naming the
  hidden directory explicitly makes a bare `rg` find it, because the dot-prefix rule governs TRAVERSAL.
  Before trusting an absence, run a POSITIVE CONTROL.
- **ASSERT THE MECHANISM, NOT THE STATE.** Theirs: a kill that takes 63s under load is still a kill. Ours:
  `activeElement` being right is also true when the render never took focus at all — nothing preserved,
  nothing exercised. The SDK's own `focus-restored` key says whether IT put focus there, and separates a
  restore from a FALLBACK.
- **WRITING A HAZARD DOWN IS NOT DESIGNING AROUND IT.** I documented in #221 that `focus-restored` does not
  fire when the element survived, then built a wait that assumed it always fires. CI caught it. Naming a
  trap creates no protection from it.
- **A DIAGNOSTIC THAT FIRES WHEN ITS CONDITION IS ALREADY HANDLED TRAINS THE READER TO SKIP IT** (#223) —
  and they skip it on the day it means something. Same family as a hash check crying tampering at a
  line-ending rewrite.
- **A MUTATION CAN GO RED FOR THE WRONG REASON, AND USUALLY DOES FIRST.** #217's descriptor assertion was
  never reached because an exit-code assertion above it failed on the cascade. Reorder so the load-bearing
  claim is checked FIRST, then re-mutate and read WHY.
- **THE FALLBACK CLAUSE IS WHERE A PROTOCOL FAILS.** "If the message is absent, scan the directory" turned a
  missing message into a confidently stale one. Absent, or a seq that has not advanced, must mean NOTHING
  NEW.
- **I WAS WRONG THREE TIMES TODAY AND EACH WAS CAUGHT BY MEASURING, NOT BY THINKING HARDER**: the rg flag,
  the #221 "observed too early" story (impossible — `render()` is one synchronous turn), and the claim that
  `--version` bypasses the NuGet lag. Each had a plausible mechanism and a wrong one.
