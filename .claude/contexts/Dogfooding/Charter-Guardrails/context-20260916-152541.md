BLOCKERS/NOTES

Carried forward, all still true:

- **NUGET HAS TWO INDEXES AND THEY LAG DIFFERENTLY.** Flat container first; the registration
  index (what `dotnet tool update` resolves against) lags further. Explicit `--version` wins the
  race often, not reliably.
- **A CI WATCH'S EXIT CODE IS NOT THE VERDICT.** Read `conclusion`, check `headSha` equals the
  PR's actual head — verified via `gh pr view --json headRefOid` before every merge this session.
- Standing authorization: **merge on green without asking**. Red still stops for a decision.
- **The Python-heredoc pipeline EATS ONE LEVEL OF BACKSLASH.** Use Write/Edit for content with
  escapes.
- Do NOT kill dotnet/testhost machine-wide.

New this session:

- **A closing keyword in a PR body is live, even inside a sentence denying it.** GitHub's parser
  does not read English; it reads `close[sd]?/fix(e[sd])?/resolve[sd]? #N` anywhere in the body.
  Write "issue N" when the PR must not close it. Memory saved.
- **"Diagnosed" is not "fixed" until the trace from the NEXT failure is read.** #221's #252 fix
  shipped, tested green, merged clean — and was wrong. The tell was in the trace all along
  (`items=2` before the drop), and it took a fresh recurrence to surface it. Don't bank a fix on
  a flaky/intermittent symptom until a failure trace has been read AFTER the fix shipped.
- **A background full-suite run and a background CI watch are not the same signal.** Several
  turns this session ran the local full suite in the background while a PR's CI ran in the
  background in parallel; both were always read to completion (`exit=0` + the per-project
  Passed!/Failed! lines) before treating either as evidence — a local suite passing does not mean
  CI will, and vice versa is not assumed either.
- **Two Playwright traps found and fixed inside NEW tests this session** (not doctrine violations,
  just cheap to forget): a class-name `--filter` on `ReviewLoopBrowserTests`' partials silently
  selects zero tests (every browser test file is a partial of ONE class — filter on the method
  name or a `[Trait("Feature", …)]`, never the file); `WaitForFunctionAsync` throws under the
  served page's CSP (`script-src` has no `unsafe-eval`) and must never be used in a browser test
  against this app.
- **A real `FileShare.None` lock is worth constructing and verifying, not stubbing.** The #221
  fix's tests hold the writer's ACTUAL lock and assert up front that it blocks a reader on the
  running platform — because .NET's file-sharing emulation on Unix is advisory and can silently
  no-op, which would make the whole test class pass for the wrong reason.

DOCTRINE (carried forward, plus new)

All prior doctrine holds (timeout ≠ absence; "no matches" ≠ "the tool looked"; assert the
mechanism not the state; one `false` for two facts is this codebase's recurring bug; a display

New this session:

- **A fix that goes green — locally, in CI, on merge — can still be wrong, and the only thing
  that proves otherwise is reading the NEXT failure's own trace rather than re-deriving the old
  theory from memory.** This is #221's whole arc in one sentence: #252 was reasoned carefully,
  tested, reviewed twice adversarially, and still fixed the wrong layer, because the reasoning
  was never checked against a fresh trace until master forced one.

  existing consumers of a format before asserting a change to it is safe.
- **A regression test suite is worth running BEFORE the PR, not just IN the PR.** #221's drain
  regression (locked log reporting exit 3 instead of exit 4) was caught by the full local suite
  pre-push, not by CI — meaning it never reached a reviewer or a merge as a red mark to explain
  away.
