DOCTRINE LEARNED THIS SESSION (worth not re-deriving)

- A guardrail fix for an IN-FLIGHT plan must be scoped to tasks that have NOT yet
  succeeded. Fixing a completed task's gate can't re-verify what's already journaled and
  costs a rewind + re-run of that task and every descendant (here: all 9, ~$79).
- Never pattern-match a tool's console text you haven't observed (#248). A zero-match
  `dotnet test --filter` under `-v q` prints NO diagnostic at all and exits 0 — the
  discriminator is a `Total:` count >= 1, not any error string. The first guard written
  keyed on the error string and was proven not to fire.
- Reverting files for hash-drift purposes must preserve bytes exactly: with
  core.autocrlf=true, `git checkout` rewrites LF→CRLF and the hash still won't match.
  Extract the blob and write it binary; prove the method on an untouched control file first.
- A task-level `tests-pass` keyed on a plan-wide trait is the "over-broad" anti-pattern
  wearing a filter. Single-guardrail probes (tautology sweep, two-sided smoke test) cannot
  see it — it only appears when you cross a filter's SCOPE with the DAG's dependency EDGES.
