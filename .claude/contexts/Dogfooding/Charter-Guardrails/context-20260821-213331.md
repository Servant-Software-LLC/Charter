DOCTRINE LEARNED THIS SESSION (carried forward, plus new)

From the prior save, still true:
- A guardrail fix for an IN-FLIGHT plan must be scoped to tasks that have NOT yet
  succeeded; fixing a completed task's gate costs a rewind of it and every descendant.
- Never pattern-match a tool's console text you have not observed (#248).
- Reverting for hash-drift must preserve bytes: with core.autocrlf=true, `git checkout`
  rewrites LF→CRLF and the hash still will not match. Extract the blob, write it binary,
  and prove the method on an untouched control file first.
- A task-level `tests-pass` keyed on a plan-wide trait is the "over-broad" anti-pattern
  wearing a filter; only visible by crossing a filter's SCOPE with the DAG's EDGES.

New this session:
- CALIBRATE A LINT AGAINST REAL DOCUMENTS BEFORE SHIPPING IT. #156 went 1 false positive
  → 0 that way, and real data taught two things reasoning had not: tracking usually sits
  in a NEIGHBOURING paragraph, and a wrapped line beginning "#223, where…" is an issue
  reference, not an ATX heading (which needs `#` + WHITESPACE).
- A TEST MUST NOT ASSUME A FACT ABOUT THE HOST. Pid 4242 is dead on Windows (pids are
  multiples of 4) and an ordinary live pid on Linux; `~/.claude/skills` on the developer's
  own machine answered for a fixture and made the missing-skill case unassertable. Inject
  the fact or pick a value no OS can produce.
- VERIFY THE SURFACE BEFORE ASSERTING AGAINST IT. `GET /api/poll` returns a bare ARRAY —
  PollEnvelope is the CLI's wrapper. An un-acked drain batch blocks the next drain for the
  visibility window (at-least-once, working as designed), so a test that polls twice
  without acking measures that window.
- PREFER THE EVENT THE PRODUCT ALREADY EMITS over a page reload in a browser test. The
  reload was unfaithful (the SDK refreshes the panel live and never navigates) AND flaky
  (it intermittently crashed WebKit). Removing it: 8/8 on both engines, 17s → 3s.
- AN ISSUE'S PREMISE CAN BE WRONG. #152 claimed `charter --version` had no drift warning;
  it shipped as #32. #155 assumed the frontmatter was unbound; it was already pinned.
  Check before building — three times this session an issue's first item already existed.
