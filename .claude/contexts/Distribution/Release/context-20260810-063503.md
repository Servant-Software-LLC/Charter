**17. #117 — annotation delivery was AT-MOST-ONCE past the socket write (PR #119).** The drain cleared
the buffer under lock; the only requeue fired if the write THREW. For Charter's few-KB payloads
`Stream.Write` lands in the kernel send buffer and returns success whether or not the peer ever reads it.
A Ctrl-C, a harness-killed shell loop, or a laptop sleep in that window **destroyed the reviewer's
annotations with no error and no trace**, and the sidecar then deleted itself because both queues looked
empty. Answers (`/answers/ack`) and the round hand-off (`/review/ack`) both HAD an ack; annotations — the
one payload that exists nowhere else once cleared — did not.
- Fixed with an in-flight holding area + `AnnotationBatch(Sequence, Annotations)` + `Ack(sequence)`.
- **A 10-second visibility window** (`AnnotationStore.DefaultVisibility`) was the key design move: the
  first cut reclaimed eagerly on every drain and produced duplicates (concurrency tests reported 3000 vs
  500). The window let those tests KEEP their exactly-once assertion instead of being weakened to fit.
- An in-flight batch must NOT hold the wake signal hot (`SyncSignalLocked` syncs on `_pending` only),
  or every later `poll --wait` spins instead of blocking.
- The sidecar persists `DurableSnapshot()` (in-flight + pending); the PANEL still shows `Snapshot()`
  (pending only) so a reviewer never sees a note as pending once it is the agent's.
- **The sequence rides a RESPONSE HEADER** (`X-Charter-Drain-Sequence`), not the body — the bare-array
  wire shape is unchanged, so an older agent keeps working and simply never acks (a re-delivery, the
  safe direction). The CLI acks only AFTER the envelope is on stdout.

**18. #118 — `charter poll --watch [--for <duration>]` (same PR #119).** `--wait` listens ~30 seconds; a
real review takes minutes to hours, so an agent had to re-run it dozens of times and nothing told it to.
The usual workaround was a shell loop — exactly what a harness kills at its timeout, straight into #117.
`--watch` keeps listening across cycles in one invocation until `--for` elapses (default **2 hours**).
Ctrl-C finishes the in-flight cycle so nothing is left half-delivered. `--for` REFUSES anything it cannot
read exactly rather than defaulting (a typo silently becoming "2 hours" is the same defect class as #115).
The docs that caused the confusion were corrected too: `--wait` returning empty means **nothing arrived
yet**, not **the review is over**.

## BLOCKERS/NOTES

**Durable distribution knowledge:**
- **Gatekeeper is about the quarantine xattr, not "is a macOS binary".** Package-manager and curl
  installs are never quarantined; only browser downloads. Settled — do not re-raise signing.
- **Ad-hoc signing is free and is the only hard Apple Silicon requirement.** Explicit and verified in
  release.yml, so a switch to Linux cross-builds fails the release rather than shipping an unrunnable
  arm64 binary.
- **A workflow that "succeeds" can still fail to publish.** The tap was invisible for 21 releases
  because opening a PR counts as success. Any channel needs an assertion the artifact is REACHABLE.
- **`RollForward` only rolls FORWARD.** A `net10.0` tool cannot run on a .NET 8 runtime.
- **Release procedure:** bump `<Version>` in `Charter.Cli.csproj` → `chore(release): X.Y.Z — <summary>`
  → `git tag vX.Y.Z && git push origin vX.Y.Z`. Pre-1.0: breaking → MINOR, fixes-only → PATCH; a new
  CLI flag or a new route is additive but still MINOR. For custom notes, let the pipeline create the
  release, THEN prepend to the generated body (`--generate-notes` would otherwise be discarded).
- `PUBLISH_NUGET=true` is set. NuGet flat-container indexing lags minutes after a successful push —
  check the job log for `Your package was pushed`, not the index.

**Delivery semantics (the newest expensive lessons):**
- **A successful socket write is not delivery.** `Stream.Write` returns when the kernel accepts the
  bytes. Any queue cleared on write-success is at-most-once, and for a few-KB payload the window is the
  whole trip. If a payload exists NOWHERE ELSE once cleared, it needs an ack.
- **Eager reclaim produces duplicates; a visibility window buys exactly-once back.** Reclaiming an
  unacked batch on the very next drain made concurrent drains hand out the same items repeatedly. The
  10s window let the concurrency tests keep the STRONGER assertion — when a fix forces you to weaken a
  test, the fix is usually the thing that is wrong.
- **Put compatibility-sensitive metadata in a header, not the body.** The drain sequence in a header
  kept the bare-array response byte-identical, so old agents keep working with zero shims.
- **When one surface is made honest, enumerate the others.** #115 existed because #107 fixed the tooltip
  and left the status line hardcoded. Grep for the claim, not the component.
- **Do not cite invariants from memory.** "The LLM lives in you, never in the binary" is real prose in
  SKILL.md:68 but is NOT invariant D1 (which is "Format: markdown + directives"). The review team caught
  this in a filed issue.

**Cross-engine testing:**
- **An untested engine is not a safe engine.** One WebKit leg found four real defects on its first run,
  in the question-answering path — the block the product exists for.
- **WebKit diverges by HOST OS too.** #113 reproduced on LINUX WebKit and passed on WINDOWS WebKit on
  identical code. A local WebKit pass is NOT evidence the CI leg passes. When a defect only reproduces
  in CI, CI is the authority — treat a red leg as "not fixed", never as flake.
- **Instrument the engine; do not reason about it.** The decisive experiment for #111 was comparing a
  Playwright click against an in-page `.click()` on the same button: the in-page click POSTed and got
  200, proving the submit path was fine and only the delivered click was lost.
- **Not every engine difference is a bug to fix.** #111b was a TEST asserting the engine's focus policy
  instead of the SDK's rule.
- **`dotnet test --logger console;verbosity=normal` omits the `Failed:` line entirely when nothing
  fails.** A gate grepping `Failed: 0` therefore fails on the HAPPY path. Key on `Test Run Successful.`
  plus a skip-count assertion. Also write gate checks as `! grep … || fail`, never `grep … && fail`:
  under the default `bash -e` an unmatched grep in an && list leaves a non-zero status.
- **Test-count is the signal, not exit code**, for `Charter.Browser.Tests` — it SKIPS without a browser,
  so a stale path yields a green run covering nothing. A complete run is **783 passed / 0 skipped**
  (Chromium and WebKit each 26/26) as of v0.11.1; #117/#118 added 21 more.

**Review-loop semantics (get these right when explaining the product):**
- **Annotations and `:::question` answers ride the SAME drain.** The poll envelope reports
  `drained: { annotations, answers }`. `charter poll` is the ONLY thing that clears either; the
  `/api/...` GETs are peeks. A bare `poll` "just to look" drains, and a following `resolve` finds
  nothing — run ONE of `poll --apply` or `resolve`.
- The difference is downstream: **an annotation needs an agent** — **an answer needs nobody**.
- **"Send to agent" is NOT a drain button.** It POSTs `/review/submit`, sets `reviewSubmitted: true`,
  and completes the wake signal so an agent in `poll --wait`/`--watch` returns instantly. It cannot call
  `poll` itself: the plan is single-writer and the server never writes it or invokes an agent.
- **`--wait` is ~30 seconds, not "until the review is done".** An empty return means nothing arrived
  YET. `--watch` is the verb that covers a whole review.

**Environment / tooling gotchas:**
- **These sessions ran on MALTBY-SURFACE (Surface Laptop 4), NOT the Dell.** Anything "installed and
  verified" here is not automatically true on the Dell or the MacBook.
- **A leftover review server holds `Charter.Cli.exe` and breaks the build.** An E2E test can leave one
  running; `Stop-Process` the specific PIDs rather than assuming a stale obj/bin.
- **`.ps1` files must be ASCII + UTF-8 BOM.** BOM-less UTF-8 is read as CP-1252 by Windows PowerShell
  5.1, so an em-dash's third byte (0x94) becomes a smart quote that terminates a string. `pwsh` 7
  defaults to UTF-8 and cannot catch it — **parse-check .ps1 in 5.1, not just 7.**
- **PowerShell advanced functions swallow `-o`.** `[Parameter(ValueFromRemainingArguments)]` adds the
  common parameters, so `-o` binds ambiguously against `-OutVariable`. Use a simple function with `$args`.
- `.gitignore`'s `[Rr]elease/` swallowed `.claude/contexts/Distribution/Release/` — fixed with
  `!.claude/contexts/**`. `git check-ignore -v` prints the last MATCHING rule, so a successful negation
  looks identical to a block; verify with `git add`.
