## COMPLETED

**1. macOS signing closed as a non-issue — Charter #9, Guardrails #377 (both CLOSED not-planned)**
The premise behind both was wrong. Gatekeeper's notarization check fires on the
`com.apple.quarantine` xattr, which is set by browsers, Mail, AirDrop and `brew install --cask` —
but NOT by `curl`, `git clone`, `dotnet tool install`, or `brew install <formula>` (Homebrew
quarantines casks, not formulae). So no shipped install path ever meets Gatekeeper, and no paid
Apple account is needed. GR #377 additionally claimed guardrails was "installed on real machines
via brew" — it wasn't; `guardrails.rb` had never landed in the tap.
The one genuine macOS requirement is different and already satisfied: Apple Silicon refuses to
exec a binary with NO signature, but **ad-hoc signing (`codesign -s -`) satisfies it, is free**,
and both repos get it automatically by building `osx-*` on `macos-latest` runners (the `osx-arm64`
leg has `smoke: true`, so it is proven to execute every release).

**2. The Homebrew tap was silently broken — remediated; root cause filed as Charter #95 / GR #413**
`bump-tap.yml` uses `peter-evans/create-pull-request` and nothing ever merged the result. The tap
had **21 open bump PRs**: `charter.rb` was pinned at **v0.1.0** while the current release was
0.8.0, and `guardrails.rb` **did not exist at all**. Invisible because the release workflow
reports success — it builds, uploads, and opens the PR; only the publish never completes.
Fixed by hand: verified checksums against the published `.sha256` assets, merged tap PRs #24 and
#14, closed 19 superseded ones. #95/#413 propose pushing the formula directly (the formula is
template-generated from release checksums — there is nothing to review) plus a post-publish
`brew audit` + `brew install` smoke test.

**3. Free leftovers broken out** — Charter #96 / GR #414 (document `xattr -dr com.apple.quarantine`
for browser downloads) and Charter #97 / GR #415 (make ad-hoc signing an EXPLICIT `codesign
--force --sign -` step so it stops depending on the runner OS). Both still OPEN.

**4. The global.json roll-forward detour — tried, measured, then abandoned (Charter #94 + PR #98,
GR #412 + PR #416, all CLOSED as superseded)**
`global.json` pinned `rollForward: latestFeature`, which accepts 8.0.xxx but rejects 9.x/10.x, so
any contributor on a current SDK hit a hard error before compiling. Measured the loosening on a
box with SDK 8.0.129 + 10.0.204: both repos built clean with 0 warnings under SDK 10 with
`TreatWarningsAsErrors` active; Guardrails' `packages.lock.json` was untouched and
`CI=true dotnet restore --locked-mode` succeeded. Two findings that outlived the approach:
  - `<RollForward>LatestMajor</RollForward>` was ALREADY in both CLI csprojs since their first
    scaffolding commits, and verified present in the PUBLISHED nupkg runtimeconfigs — so
    `dotnet tool install -g` already worked on a runtime-newer machine.
  - Adding `RollForward` to `Directory.Build.props` (to make `dotnet test` work) was DROPPED as
    fighting the grain: that file exists to eliminate local-vs-CI divergence, and this would have
    committed exactly that at the runtime layer. The capability stayed a per-contributor
    `DOTNET_ROLL_FORWARD=LatestMajor` env-var opt-in instead.

## BLOCKERS/NOTES

**Durable distribution knowledge (the expensive lessons):**
- **Gatekeeper is about the quarantine xattr, not about being a macOS binary.** Package-manager
  and curl installs are never quarantined. Only browser downloads are. Do not re-raise signing as
  a blocker — it is settled and both issues are closed.
- **Ad-hoc signing is free and is the only hard Apple Silicon requirement.** Today it is an
  implicit side effect of using `macos-latest` runners; #97 exists to make that explicit before a
  cost-saving switch to Linux cross-builds silently ships an unrunnable arm64 binary.
- **A release workflow that "succeeds" can still fail to publish.** The tap disaster was invisible
  for 21 releases because opening a PR counts as success. Any new channel needs an assertion that
  the artifact is REACHABLE, not just produced.
- **`RollForward` only rolls FORWARD.** A `net10.0` tool cannot run on a .NET 8 runtime. This is
  why the TFM bump is breaking for NuGet consumers and harmless for Homebrew/direct-download users
  (self-contained binaries bundle their own runtime).
- **Test-count is the signal, not exit code**, for `Charter.Browser.Tests`: it SKIPS rather than
  fails when Chromium is missing, so a stale Playwright path yields a green run covering nothing.
  A complete Charter run is **759 passed / 0 skipped**.
- **Release procedure:** bump `<Version>` in `Charter.Cli.csproj` → commit `chore(release): X.Y.Z —
  <summary>` → `git tag vX.Y.Z && git push origin vX.Y.Z`. Pre-1.0, a breaking change takes the
  MINOR position. To add custom release notes, let the pipeline create the release first, then
  PREPEND to the generated body.
- **Repo variable `PUBLISH_NUGET=true`** is set on Charter — releases really do publish to NuGet.
- NuGet flat-container indexing lags several minutes after a successful push; absence there is not
  evidence of failure. Check the push job log for `Your package was pushed`.

**macOS onboarding (David is a lifelong Windows dev; this is his first Mac):**
- **Visual Studio for Mac is retired** (Aug 2024) — the choice is VS Code + C# Dev Kit, or Rider
  (whose free tier is non-commercial only; check terms against Servant Software LLC usage).
- Install Xcode **Command Line Tools**, not full Xcode (the Homebrew installer pulls CLT itself).
- On Apple Silicon Homebrew lives at `/opt/homebrew` and is NOT on PATH by default — the
  `eval "$(/opt/homebrew/bin/brew shellenv)"` line in `~/.zprofile` is the step everyone misses.
  He hit exactly this (`zsh: command not found: brew`).
- `~/.dotnet/tools` is likewise not on PATH by default — same class of trap.
- Beware **shadowing** when verifying install paths: `brew` puts `charter` in `/opt/homebrew/bin`,
  so a bare `charter --version` after `dotnet tool install` may silently run the brew binary. Use
  `which -a charter` and invoke the explicit path.
- Playwright's installer is a **PowerShell** script, so `pwsh` (`brew install --cask powershell`)
  is genuinely required to run Charter's full suite on macOS.
