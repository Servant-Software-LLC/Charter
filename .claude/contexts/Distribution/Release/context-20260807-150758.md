## BLOCKERS/NOTES

**Durable distribution knowledge (the expensive lessons):**
- **Gatekeeper is about the quarantine xattr, not "is a macOS binary".** Package-manager and curl
  installs are never quarantined; only browser downloads. Settled — do not re-raise signing.
- **Ad-hoc signing is free and is the only hard Apple Silicon requirement.** Now explicit and verified
  in release.yml, so a switch to Linux cross-builds fails the release instead of silently shipping an
  unrunnable arm64 binary.
- **A workflow that "succeeds" can still fail to publish.** The tap was invisible for 21 releases
  because opening a PR counts as success. Any channel needs an assertion the artifact is REACHABLE,
  not just produced — that is what the new `verify` job is.
- **`RollForward` only rolls FORWARD.** A `net10.0` tool cannot run on a .NET 8 runtime.
- **Test-count is the signal, not exit code**, for `Charter.Browser.Tests` — it SKIPS without Chromium,
  so a stale Playwright path yields a green run covering nothing. A complete run is **771 passed /
  0 skipped** (was 759 before #106's 4 tests and #93's 8).
- **Release procedure:** bump `<Version>` in `Charter.Cli.csproj` → `chore(release): X.Y.Z — <summary>`
  → `git tag vX.Y.Z && git push origin vX.Y.Z`. Pre-1.0, a breaking change takes the MINOR position.
  For custom notes, let the pipeline create the release, THEN prepend to the generated body.
- `PUBLISH_NUGET=true` is set on Charter. NuGet flat-container indexing lags minutes after a
  successful push — check the job log for `Your package was pushed` rather than the index.

**Review-loop semantics (get these right when explaining the product):**
- **Annotations and `:::question` answers ride the SAME drain.** The poll envelope reports
  `drained: { annotations, answers }`. `charter poll` is the ONLY thing that clears either; the
  `/api/...` GETs are peeks. So a bare `poll` "just to look" drains, and a following `resolve` finds
  nothing — run ONE of `poll --apply` or `resolve`.
- The difference is downstream: **an annotation needs an agent** (advice with a source line; the agent
  decides what to edit) — **an answer needs nobody** (it has a defined home, written back mechanically).
- **"Send to agent" is NOT a drain button.** It POSTs `/review/submit` and sets `reviewSubmitted: true`
  — "this round is done". It also completes the `AnnotationStore` wake signal, so an agent blocked in
  `poll --wait` is woken instantly. The button cannot call `poll` itself because the plan is
  single-writer and the server never writes it or invokes an agent.

**Environment / tooling gotchas:**
- **This session ran on MALTBY-SURFACE (Surface Laptop 4), NOT the Dell.** Anything "installed and
  verified" here is not automatically true on the Dell or the MacBook.
- **`.ps1` files must be ASCII + UTF-8 BOM.** `demo.ps1` was unparseable in Windows PowerShell 5.1:
  BOM-less UTF-8 is read as CP-1252, so an em-dash's third byte (0x94) becomes a smart double-quote,
  which PowerShell honours as a string delimiter. `pwsh` 7 defaults to UTF-8 and could not catch it —
  **parse-check .ps1 in 5.1, not just 7.**
- **PowerShell advanced functions swallow `-o`.** `[Parameter(ValueFromRemainingArguments)]` adds the
  common parameters, so `-o` binds ambiguously against `-OutVariable`. Use a simple function with
  `$args`.
- `.gitignore`'s `[Rr]elease/` swallowed `.claude/contexts/Distribution/Release/` — fixed with
  `!.claude/contexts/**`. `git check-ignore -v` prints the last MATCHING rule, so a successful negation
  looks identical to a block; verify with `git add`.
